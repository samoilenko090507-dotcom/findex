# findex – Лабораторна робота 2: Інвертований індекс

Проєкт реалізує повноцінний інвертований індекс з підтримкою булевого пошуку (AND, OR, NOT), оптимізацією пам'яті через `slots` та двійковою серіалізацією на базі `array('I')`.

## 1. Порівняння оптимізацій пам'яті (tracemalloc)

Вимірювання пікового споживання пам'яті при зберіганні постингів для текстового корпусу:

| Варіант структури | Пікова пам'ять | Різниця |
| :--- | :--- | :--- |
| Звичайний `@dataclass` (без слотів) | 4.33 МБ | Базовий рівень |
| `@dataclass(slots=True)` | 3.26 МБ | **-24.7% (економія ~1.07 МБ)** |
| Пари `array('I')` у словнику | 4.61 МБ | +6.5% |

**Куди пішли байти:**
- Звичайний клас виділяє динамічний словник `__dict__` для кожного екземпляра постингу, що створює значний оверхед пам'яті при сотнях тисяч записів.
- Використання `__slots__` фіксує структуру атрибутів на рівні C-структури Python і повністю прибирає `__dict__`, що дало зниження пам'яті майже на чверть.
- Варіант з `array('I')` виявився важчим через оверхед створення великої кількості окремих об'єктів масивів у Python для низькочастотних термінів.

## 2. Порівняння серіалізації: Binary vs Pickle

| Формат | Розмір файлу | Час збереження | Час завантаження | Безпека |
| :--- | :--- | :--- | :--- | :--- |
| **Pickle** | 608.29 КБ | 0.0562 с | 0.0880 с | **Небезпечно** (можливе виконання довільного коду / RCE) |
| **Binary (`struct` + `array`)** | **469.32 КБ** | **0.0405 с** | **0.0504 с** | **Безпечно** (строга типізація, лише сирі байти) |

> **Коментар щодо безпеки:** `pickle` десеріалізує довільні об'єкти Python через протокол `__reduce__`, що дозволяє зловмиснику виконати системні команди в ОС при завантаженні чужого файлу індексу. Власний двійковий формат читає виключно цілі числа та байти тексту, унеможливлюючи вразливості типу RCE.

## 3. Бенчмарк пошуку: Двовказівниковий Merge vs Set

Вимірювання середнього часу виконання запиту (500 прогонів):

| Тип запиту | Терміни | Двовказівниковий `merge` | Множини `set` |
| :--- | :--- | :--- | :--- |
| **Найчастіші слова** | `'start of'` | **4.05 мкс** | 4.64 мкс |
| **Найрідкісніші слова** | `'newsletter subscribe'` | 5.00 мкс | **4.59 мкс** |

Алгоритм злиття двох вказівників (`merge`) показує перевагу на великих списках однакової довжини, оскільки використовує перевагу попереднього сортування за `doc_id` і не потребує динамічного хешування та створення нових об'єктів у купі, на відміну від `set.intersection()`.
