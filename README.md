# findex – Лабораторна робота 1

## Опис проєкту
Проєкт реалізує читання текстового корпусу та його токенізацію двома шляхами: лінивим потоковим конвеєром через генератори (`yield`) та жадібним завантаженням усіх даних у списки оперативної пам'яті.

## Результати вимірювань (tracemalloc)
Корпус містить 4 документи загальним обсягом 370 208 токенів (16 444 унікальних слів).

| Підхід | Час виконання (с) | Пікова пам'ять (МБ) |
| :--- | :--- | :--- |
| Потоковий (генератори / yield) | 0.7069 | 13.22 |
| Жадібний (списки в пам'яті) | 0.6073 | 25.49 |

## Reflection (Висновки)
1. **Куди пішла пам'ять у жадібній версії:** жадібний метод одночасно завантажує та утримує в оперативній пам'яті повні тексти всіх документів, а потім будує величезний список з понад 370 тисяч окремих рядків-токенів. Через це пікове споживання пам'яті досягло 25.49 МБ.
2. **Перевага генераторів:** функції `iter_documents` та `tokenize` обробляють дані «на льоту» через ключове слово `yield`. У пам'яті в кожен момент часу зберігається лише один документ або поточний токен, а використані об'єкти одразу очищаються збирачем сміття (Garbage Collector). Це знизило пікове навантаження на пам'ять майже вдвічі (до 13.22 МБ).
3. **Токенізація:** реалізовано нормалізацію Unicode (NFKC), переведення у нижній регістр, підтримку внутрішніх апострофів/дефісів у словах та збереження чисел як окремих токенів.
